# End-to-end example

This page follows one plugin from code to a running step: write it, test it without a connection, build the plugin
package, preview and apply its registration, then read its trace in Dataverse. It assumes a solution scaffolded by
[`vela init`](scaffold.md) with the `Account` model generated by [`vela models`](models.md), as in the
[Quickstart](../getting-started/quickstart.md), and an existing unmanaged solution `ZavaSales` in your development
environment.

`Zava.Plugins.Account.Plugins`, with `using Vela.Plugin;` and `using Zava.Shared.Models.Generated;` inside the
namespace block (see [Namespaces and usings](scaffold.md#namespaces-and-usings)).

## 3. Build the plugin package

```bash
dotnet build src/Zava.Plugins -c Release
```

Use `dotnet build`, not `dotnet pack`: the build runs `GeneratePackageOnBuild` and writes the `.nupkg` to
`artifacts/`, while a `dotnet pack` without a prior build emits a package with no assembly.

## 4. Preview the changes

```bash
vela plan --packages-dir artifacts --solution ZavaSales --interactive
```

`plan` is read-only. On a terminal it prints a colored preview: a `summary: +N -N ~N` line and the ordered
operations. Piped, or with `--json`, it prints a JSON document.

`--solution` names the unmanaged solution that every component is added to. `plan` and `apply` refuse a solution that
is managed in the target environment, which usually means the connection points at a test or production
environment. Dataverse imports a plugin package only when its name carries the publisher prefix:
`vela init --publisher-prefix zava` names it `zava_Zava.Plugins`, and an unprefixed package gets the prefix of the
solution's publisher.

## 5. Apply them

```bash
vela apply --packages-dir artifacts --solution ZavaSales --interactive
```

On a terminal `apply` shows the plan and asks you to type `yes` (`--auto-approve` skips the prompt in CI). It
publishes the package, waits for Dataverse to expose the plugin type, then registers the step and its image. A second
run with no change does nothing. If a run fails partway, the resume report on stderr lists what completed: fix the
cause and run `apply` again. See [Plan and apply](plan-apply.md) for authentication and options.

## 6. Verify in Dataverse

Rename an account, then read the trace line with
[`vela logs`](cli-overview.md#reading-execution-logs-vela-logs) (`vela logs --since 1h -i`) or in the Plug-in Trace
Log. Trace logging must be
[enabled on the environment](https://learn.microsoft.com/power-apps/developer/data-platform/logging-tracing#enable-trace-logging).
